# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| 1.0.x | Yes |
| Earlier versions | No; update to the latest 1.0.x release before reporting. |

Security fixes are developed for the latest supported release.

## Reporting a vulnerability

Do not report vulnerabilities in public issues or pull requests. Use GitHub's
[Private Vulnerability Reporting](https://github.com/M003aad/Orbit/security/advisories/new)
for this repository. If that channel is unavailable, email
[188705139+M003aad@users.noreply.github.com](mailto:188705139+M003aad@users.noreply.github.com).

Include the affected Orbit and browser versions, security impact, and
reproduction steps in an authorized test environment. Remove personal data and
secrets from any logs or screenshots.

## Response and remediation

The maintainer aims to acknowledge reports within five business days and
provide an initial assessment within ten business days. Confirmed issues will
be prioritized by severity; fixes will be released as soon as practical after
validation. Reporters will be kept informed when a fix or mitigation is
available. Please allow time for investigation and remediation before public
disclosure.

## Scope

Reports should demonstrate a security impact in Orbit, such as unintended
access to browser data, unsafe handling of imported settings, or an extension
action occurring without user intent. Issues originating solely in a browser
or website should be reported to that project's security team. Do not access,
modify, or disrupt systems or data that you do not own or have permission to
test.
